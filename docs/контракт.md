# Пульт — контракт данных (версия 1)

Общий документ для ядра (Rust) и интерфейса (React). Все адреса здесь выдуманные.
В репозиторий кладётся как `docs/контракт.md`. Меняется только согласованно: сначала
этот файл, потом обе стороны.

## 1. Инвентарь

Каталог с файлом `инвентарь.yaml`. Приложению задаётся **путь к каталогу** (настройка).
Если каталог — git-клон, приложение по расписанию делает `git pull --ff-only`; это
удобство, а не условие работы. Личные узлы — второй файл той же схемы в папке данных
приложения, сливается поверх.

```yaml
версия_схемы: 1
узлы:
  - id: интернет
    название: Интернет
    вид: внешнее
    проверки:
      - {вид: tcp, адрес: "1.1.1.1:443"}
      - {вид: tcp, адрес: "example.com:443"}

  - id: хост-а
    название: Хост А
    вид: хост
    группа: прод
    зависит_от: [интернет]
    проверки:
      - {вид: tcp, адрес: "a.example.com:22"}
    сбор:
      ssh: "host-a"                 # алиас из ~/.ssh/config или user@host
      что: [docker, wireguard]

  - id: туннель-дом
    название: WireGuard до дома
    вид: туннель
    зависит_от: [хост-а]
    проверки:
      - {вид: tcp, адрес: "10.0.0.2:22", откуда: хост-а}   # выполняется НА узле хост-а

  - id: хост-б
    название: Хост Б (за туннелем)
    вид: вм
    группа: дом
    зависит_от: [туннель-дом]
    сбор:
      ssh: "user@10.0.0.2"
      через: хост-а                  # вложенный ssh с узла хост-а
      что: [docker]

  - id: панель
    название: Панель задач
    вид: контейнер
    на: хост-б                       # размещён на узле: обязательная зависимость + источник фактов
    контейнер: tasks-panel           # имя контейнера на узле `на`
    проект: Задачи                   # папка на карте внутри хоста
    проверки:
      - {вид: http, url: "https://tasks.example.com/health"}
    доступ:
      как_зайти: "https://tasks.example.com"
      секрет: "хранилище → токен панели"
      у_кого: [alice, bob]
    ссылки:
      - {название: Логи, url: "https://logs.example.com"}
```

Поля узла:

| Поле | Обяз. | Смысл |
|---|---|---|
| `id` | да | уникален во всём инвентаре |
| `название` | да | подпись на карточке |
| `вид` | да | `внешнее`, `хост`, `вм`, `контейнер`, `сервис`, `туннель` — влияет только на значок |
| `группа` | нет | справочное: подпись в панели узла |
| `проект` | нет | к какому проекту относится сервис. На карте сервисы хоста разложены по папкам проектов; без проекта — папка «Общее» |
| `скрыть` | нет | `true` — узел описан и проверяется, но на карте и в счётчиках его нет: служебное, чьё «работает» никому не нужно (заглушка «сайт обновляется»). Контейнер такого узла не становится «не описан». Корнем отказа и поводом для уведомления скрытый узел не бывает; отказ его видимого потомка тогда сам корень. Скрывать стоит листья: видимые дети скрытого узла останутся на карте без родителя |
| `на` | нет | узел размещения. Движок считает его обязательной зависимостью; факты о контейнере или ВМ берутся из сбора этого узла |
| `зависит_от` | нет | список id; обязательны **все** (логическое И). Альтернативных путей в версии 1 нет |
| `проверки` | нет | см. ниже |
| `сбор` | нет | только у узлов, с которых собираются факты |
| `контейнер` | нет | точное имя контейнера на узле `на` |
| `compose` | нет | `{проект, сервис}` — сопоставление по меткам compose вместо имени; нужно там, где имя меняется между выкатами (`app-backend-1` / `-2`). Несколько экземпляров сервиса — один узел: «работает», если работает хотя бы один |
| `вм` | нет | номер ВМ или LXC на узле `на` |
| `ожидается` | нет | `работает` (по умолчанию), `остановлен` (остановка — норма, например мигратор) или `любое` |
| `доступ`, `ссылки` | нет | справочные, движок их не читает |

Проверки:

| Вид | Поля | Успех |
|---|---|---|
| `tcp` | `адрес`, `таймаут_мс` (3000), `откуда` | соединение установлено |
| `http` | `url`, `ожидать` (200; можно список), `таймаут_мс` (5000), `откуда` | код из списка |
| `ollama` | `url` — адрес сервера (`http://10.0.0.5:11434`), `ожидать_модели` (список), `таймаут_мс` (5000), `откуда` | сервер ответил списком моделей и все ожидаемые в нём есть |

`ollama` выполняет `GET /api/tags` и `GET /api/ps`: факт — «отвечает за 40 мс · моделей: 5 · в памяти:
qwen3:8b (GPU)», «не отвечает: <причина>» или «нет модели X». Имя в `ожидать_модели` без метки
(`qwen3`) подходит под любую метку модели, с меткой (`qwen3:8b`) — точное. **Генерацию цикл не
запускает**: она грузит модель в видеопамять и мешает рабочим запросам; настоящий запрос к модели —
только командой `ollama_ask` по кнопке (раздел 3). `url` и имена моделей проверяются по белому
списку символов всегда: они попадают в скрипт сбора.

`откуда: <id>` — проверка выполняется не с машины пользователя, а на указанном узле,
внутри его сеанса сбора. Нужна для адресов, видимых только из закрытой сети.

Сбор: `ssh` — цель; `через` — id узла, с которого выполняется вложенный ssh; `ключ` —
путь к ключу на той машине, которая выполняет этот ssh (для вложенного — на узле
`через`), передаётся как `-i`; `что` — встроенные сборщики из списка `docker`,
`wireguard`, `proxmox`. Значения `ssh` и `ключ` при загрузке проверяются по белому
списку символов (буквы, цифры, `@ . _ - / ~ :`), чтобы из инвентаря нельзя было
подставить команду. **Произвольных команд
в инвентаре нет**: репозиторий с данными не должен быть источником исполняемого кода.

Проверка инвентаря при загрузке (любая ошибка — снимок отклоняется целиком):
уникальность id; все ссылки (`на`, `зависит_от`, `через`, `откуда`) существуют; нет
циклов по `на` + `зависит_от`; `через` и `откуда` указывают на узел со `сбор`;
известные `вид` узла и проверки; `версия_схемы` не выше поддерживаемой (иначе ошибка
«обнови Пульт»). Незнакомые поля не ошибка — предупреждение, одно на поле со списком или
числом узлов: новое поле схемы у не обновившегося Пульта не должно выглядеть аварией.

Отклонённый инвентарь не заменяет действующий: приложение работает на последнем
принятом снимке (он сохраняется в папке данных) и показывает текст ошибки.

## 2. Состояние узла

Движок — чистая функция `оценить(инвентарь, измерения, сейчас) → состояния`.
Собственный результат узла и предполагаемая причина хранятся раздельно.

```ts
type OwnStatus =
  | 'ok'         // нет свежих отказов и есть хотя бы одно свежее успешное измерение;
                 // не полученное и устаревшее при этом перечислено в hints («часть данных
                 // не получена: …») и стоит в checks строкой с ok: null
  | 'fail'       // есть собственный доказанный отказ
  | 'unknown'    // узнать нечем: нет пути наблюдения или измерений ещё не было
  | 'stale'      // последнее измерение старше срока годности
  | 'unchecked'; // у узла нет ни проверок, ни фактов сбора

interface CheckResult {
  kind: 'tcp' | 'http' | 'container' | 'vm' | 'collect'
      | 'ollama'            // проверка ollama
      | 'mcp' | 'process';  // только у узлов MCP (раздел 7): настоящая проверка и «есть ли процесс»
  target: string;          // что проверяли, по-человечески
  from: string | null;     // id узла, с которого выполнена, либо null — с этой машины
  ok: boolean | null;      // null — выполнить не удалось
  fact: string;            // наблюдаемый факт: «порт 22: таймаут 3 с»
  latencyMs: number | null;
  measuredAt: string;      // ISO 8601
  models?: string[];       // только у ollama: модели сервера — из них выбирают, какую спросить
}

interface ContainerFacts {
  state: string;           // running | exited | restarting | ...
  exitCode: number | null;
  oomKilled: boolean | null;
  health: string | null;   // healthy | unhealthy | starting | null
  restartCount: number | null;
  startedAt: string | null;
  finishedAt: string | null;
  image: string | null;
}

interface NodeState {
  id: string;
  own: OwnStatus;
  confirmed: boolean;      // состояние подтверждено двумя циклами подряд
  fact: string;            // главный наблюдаемый факт — заголовок карточки
  hints: string[];         // возможные причины, не утверждения
  isRoot: boolean;         // own = fail и среди обязательных предков нет отказавших
  blockedBy: string[];     // id отказавших корней среди обязательных предков
  checks: CheckResult[];
  container: ContainerFacts | null;
  measuredAt: string | null;
  since: string | null;    // с какого времени own не менялся
}
```

Правила:

1. Обязательные предки узла — `зависит_от` плюс `на`, транзитивно.
2. `own = fail`, если не прошла хотя бы одна собственная проверка или факт сбора
   говорит «не запущен».
3. Если сбор с узла размещения не удался, факты о его контейнерах — `unknown`, а не
   `fail`. Собственные сетевые проверки контейнера при этом учитываются как обычно.
4. Корней может быть несколько. Узел со `скрыть: true` корнем не бывает и в `blockedBy` не
   попадает. Отказ ребёнка при отказавшем родителе не скрывается:
   `own` остаётся `fail`, `isRoot = false`, `blockedBy` указывает на корень.
5. Срок годности измерения — три интервала его проверки. После пробуждения машины из
   сна все измерения считаются устаревшими и цикл запускается немедленно.
6. Ответ, пришедший от уже завершённого цикла, отбрасывается.
7. `confirmed` — два цикла подряд с одним и тем же `own`. Уведомления шлются только
   по подтверждённым сменам состояния и только для корней.
9. Контейнера нет в успешном полном списке сбора: при `ожидается: работает` это
   `fail` с фактом «контейнер не найден»; при `остановлен` и `любое` — `ok`
   («контейнера нет, так и должно быть»: мигратор запускается с `--rm` и удаляется).
   При `остановлен` работающий контейнер — не отказ, а `ok` с фактом «сейчас запущен».
8. Заголовок карточки — наблюдаемый факт. Причины — только в `hints` и только как
   предположения. «Нехватка памяти» пишется лишь при `oomKilled = true`; код 137 без
   него — «остановлен принудительно (SIGKILL)».

Как интерфейс показывает состояние:

| Условие | Вид карточки |
|---|---|
| `own = ok` | зелёная |
| `own = fail`, `isRoot` | красная, с фактом |
| `own = fail`, не корень | приглушённо-красная: факт + «причина выше: …» |
| `own = unknown` или `stale`, есть `blockedBy` | серая: «неизвестно, причина выше: …» |
| `own = unknown`, `blockedBy` пуст | серая: факт (например «нет пути наблюдения») |
| `own = stale` | серая с часами: «данные от 14:32» |
| `own = unchecked` | нейтральная рамка: факт — «не проверяется», у MCP-сервера «сейчас не запущен: …» |

## 3. Снимок и события

```ts
interface NodeView {             // статическая часть, из инвентаря
  id: string; title: string;
  kind: string;                  // `вид` из инвентаря либо 'mcp' — узел, найденный на этой машине (раздел 7)
  group: string | null;
  project: string | null;        // поле `проект`
  on: string | null; dependsOn: string[];
  access: { how: string | null; secret: string | null; who: string[] } | null;
  links: { title: string; url: string }[];
  undeclared: boolean;           // найден сбором, в инвентаре не описан
  hasLogs: boolean;
  mcp?: McpInfo | null;          // только у узлов MCP
}

interface Snapshot {
  cycle: number;
  takenAt: string;
  inventory: { path: string | null; commit: string | null; loadedAt: string | null; error: string | null; warnings: string[] };
  nodes: NodeView[];
  states: Record<string, NodeState>;
}
```

Узлы со `скрыть: true` не попадают ни в `nodes`, ни в `states`, ни в событие `pult://states`.

Команды Tauri (`invoke`):

| Команда | Аргументы | Ответ |
|---|---|---|
| `get_snapshot` | — | `Snapshot` |
| `recheck` | `{ id?: string }` | — (результат придёт событием) |
| `get_history` | `{ id: string, limit?: number }` | `{ at: string; own: OwnStatus; fact: string }[]` |
| `open_logs` | `{ id: string, tail?: number }` | `{ streamId: string }` |
| `close_logs` | `{ streamId: string }` | — |
| `get_settings` / `set_settings` | `Settings` | `Settings` |
| `check_environment` | — | `EnvCheck[]` |
| `get_update_blocker` | — | `string \| null` (по-русски, почему обновление не поставить, например запуск из временной копии macOS; `null` — можно) |
| `open_url` | `{ url: string }` | — (только http/https, открывается в системном браузере) |
| `ollama_ask` | `{ id: string, model: string }` | `OllamaAnswer` — одна настоящая генерация, только по кнопке |
| `mcp_probe` | `{ id: string }` | `McpProbe` — рукопожатие с MCP-сервером, только по кнопке (раздел 7) |

`ollama_ask` спрашивает сервер первой проверки `ollama` узла: `POST /api/generate` с `stream: false`
и `num_predict: 1`, предел — 60 с; с этой машины или с узла `откуда`, тем же путём, что и проверка
(цепочка ssh, скрипт сбора). `model` — только имя из `models` последней проверки этого узла; другое
ядро отклонит. `keep_alive` не передаётся: срок жизни уже загруженной модели не меняется. Модель при
этом загружается в память сервера — интерфейс пишет это рядом с кнопкой.

```ts
interface OllamaAnswer { ok: boolean; fact: string; seconds: number | null }
// fact: «ответила за 3.2 с, из них загрузка в память — 2.8 с» либо текст ошибки сервера как есть
```

```ts
interface Settings { inventoryPath: string | null; notifications: boolean; autostart: boolean; }
interface EnvCheck { name: string; ok: boolean; detail: string; }  // ssh, git, ключ, доступ к инвентарю
```

События (`listen`):

| Событие | Данные | Когда |
|---|---|---|
| `pult://snapshot` | `Snapshot` | старт, смена инвентаря |
| `pult://states` | `{ cycle: number; states: NodeState[] }` | после каждого цикла — только изменившиеся |
| `pult://log` | `{ streamId: string; lines: string[] }` | пока открыта вкладка логов |
| `pult://log-end` | `{ streamId: string; error: string | null }` | поток закрыт |

## 4. Сбор по ssh

- Один сеанс на цепочку за цикл. Внешний вызов: `ssh -T -o BatchMode=yes
  -o ConnectTimeout=8 -o ServerAliveInterval=5 -o ServerAliveCountMax=2 <цель> sh -s`,
  скрипт подаётся на вход. Вложенные хосты (`через`) опрашиваются из того же скрипта
  такими же вызовами с собственным пределом времени.
- Скрипт только читает. Каждая команда — отдельная секция с кодом выхода:

  ```
  @@pult 1 host=хост-а section=docker rc=0
  ...строки JSON...
  @@pult 1 host=хост-а section=wireguard rc=1
  ...текст ошибки...
  ```

  Всё до первой строки `@@pult` (баннеры, предупреждения) отбрасывается.

  Имена секций: `docker`, `wireguard`, `proxmox` — сборщики из `что`; `check.N` — N-я (с нуля)
  проверка с `откуда: <этот узел>` в порядке инвентаря (у `ollama` в секции — тела ответов, см. ниже); `ssh` — итог вложенного ssh, его печатает
  родитель после выхода (`rc` — код ssh, тело — его stderr); `end` — метка конца хоста.
- **Полнота секции.** Секция хоста принимается, только если за ней пришёл заголовок следующей
  секции того же хоста (кроме `ssh`) или кого-то из его вложенных. Последнюю закрывает `end`.
  Оборванная секция — «не получено» (`Missing`), а не пустой список: неполный `docker ps` выглядел
  бы как «контейнер исчез». Непонятная строка внутри секции (не JSON у `docker`, нет частей
  `@qm`/`@pct` у `proxmox`) — тоже «узнать не удалось»; предупреждения `WARNING: …` docker допустимы.
- Проверка, которую нечем выполнить (нет `nc` с `-z`, нет `bash`, нет `curl`), отвечает
  ненулевым `rc` секции — это «узнать не удалось», а не «порт закрыт».
- Предел времени на каждом переходе: `timeout`, если он есть на хосте, иначе встроенный сторож;
  вложенный ssh — с тем же keepalive, что и внешний.
- Ошибка команды (`rc ≠ 0`) — это «узнать не удалось», а не «объектов нет». Исчезновение
  контейнера фиксируется только по успешному полному ответу.
- `docker ps -a` (остановленные тоже), сопоставление по имени контейнера. Из `inspect`
  берутся только поля из `ContainerFacts`; переменные окружения не читаются и не
  сохраняются.
- Проверка `ollama` с узла возвращает тела ответов, разбирает их Пульт. Каждая строка тела помечена
  именем запроса (`tags|…`, `ps|…`; у `ollama_ask` — `ask|…`): сервер не может напечатать строку
  `@@pult` и подделать чужую секцию. Последняя строка запроса — `<имя>|@<код http> <секунды> <код curl>`.
  Тело ограничено 256 КБ; нет итоговой строки — тело обрезано, это «узнать не удалось».
- `ollama_ask` идёт отдельным сеансом по цепочке `через` без сборщиков; переходы к узлу с вопросом
  ждут предел генерации с запасом (а не обычные 15 с), весь сеанс — до 90 с.
- Общий предел цикла — 45 секунд; по истечении процесс завершается, уже полученные
  секции сохраняются. Новый цикл не начинается, пока идёт предыдущий.
- Цикл сбора — раз в 60 секунд, у сбора свой счётчик циклов и своё отбрасывание опоздавших
  ответов; ответ каждой цепочки сохраняется сразу. `recheck` запускает и сбор.
- Контейнер, который сбор увидел, а инвентарь не описывает, попадает в снимок узлом
  `<хост>/<имя>` с `undeclared: true`, `ожидается: любое` (красным не становится).
- Пиры WireGuard узлами не становятся: у узла `вид: туннель` в `hints` — время последнего
  handshake пира, чьи allowed-ips содержат адрес из проверки туннеля (старше 3 минут —
  «похоже, не на связи»).
- Логи: `docker logs --tail N -f`, ограниченный буфер, процесс завершается при закрытии
  вкладки (`close_logs`) и при закрытии окна. Цепочка ssh до хоста строится по `через`;
  имя контейнера compose берётся из последнего сбора.
- Windows: дочерние процессы запускаются напрямую, без оболочки, с флагом
  `CREATE_NO_WINDOW` и перенаправленными потоками. Пути к `ssh` и `git` определяются
  явно и показываются в проверке окружения.

## 5. Рой агентов

Вкладка «Рой» — только чтение. Ядро сводит два источника: хаб роя (`GET /state` и поток
`GET /events`, адрес и токен — из `fleet.json` диспетчера, как у CLI роя) и файлы
локального диспетчера этой машины (`~/.claude/orchestrator`). Локальное показывается и
при недоступном хабе. Токен интерфейсу не передаётся.

```ts
type HubState = 'off' | 'connecting' | 'ok' | 'unavailable';  // off — рой на машине не настроен
type Presence = 'online' | 'offline' | 'unknown';            // unknown — хаба нет и локальной отметки нет
type LockProblem = 'offline' | 'overdue' | 'silent';          // держатель не в сети / держит дольше срока / молчит ≥ 20 мин

interface FleetView {
  takenAt: string;
  hub: { state: HubState; address: string | null; error: string | null; lastOkAt: string | null };
  machine: string | null;                 // имя этой машины, если файлы диспетчера его назвали
  sessions: FleetSession[];               // все, о ком что-то известно: в сети и упомянутые в замках, заявках, задачах
  locks: FleetLock[];                     // сначала проблемные
  fleetResources: FleetResource[];        // общие ресурсы хаба, включая свободные
  claims: FleetClaim[];                   // сначала пересечения
  board: FleetNote[];                     // одна заметка на сессию, свежие сверху
  tasks: FleetTask[];                     // в работе → в очереди → провалены → готовы
  local: { dir: string; found: boolean; resources: FleetResource[]; runs: FleetRun[]; errors: string[] };
  problems: number;                       // замки с проблемой + файлы с пересечением
}

interface FleetSession {
  id: string; name: string | null; machine: string | null; local: boolean;
  presence: Presence; silent: boolean; lastSeenAt: string | null;
  cwd: string | null; note: string | null;  // папка и последняя заметка — чтобы узнать сессию без имени
}
interface FleetLock {
  key: string; resource: string; scope: 'fleet' | 'local'; repo: string | null;
  session: string | null;                 // null — замок свободен, но к нему стоит очередь
  since: string | null; ttlMin: number | null; units: number;
  command: string | null; cwd: string | null;
  queue: { session: string; since: string; reason: string | null }[];
  problem: LockProblem | null;
}
interface FleetResource { name: string; label: string | null; capacity: number; used: number }
interface FleetClaim { file: string; repo: string | null; sessions: { session: string; since: string }[]; overlap: boolean }
interface FleetNote { session: string; text: string; task: string | null; cwd: string | null; at: string }
interface FleetTask {
  id: string; title: string; status: 'TODO' | 'IN_PROGRESS' | 'DONE' | 'FAILED'; priority: string;
  executor: string | null; machine: string | null; session: string | null; node: string | null; attempts: number;
  createdAt: string | null; startedAt: string | null; finishedAt: string | null; note: string | null;
}
interface FleetRun { resource: string; session: string | null; command: string | null; cwd: string | null; startedAt: string | null; background: boolean }
```

Правила:

1. «В сети» — по хабу: сессия есть в его списке живых (порог хаба — час тишины). Хаб
   недоступен — по локальной отметке присутствия `fleet-beat-<сессия>.json` с тем же порогом.
2. Проблема замка: держатель не в сети → `offline`; иначе держит дольше `ttlMin` → `overdue`;
   иначе держатель молчит 20 минут и дольше → `silent`.
3. Пересечение заявок — один файл (в одном репозитории) у двух и более сессий, которые не
   ушли из сети: предупреждение о призраке хуже, чем никакого.
4. Хаб пропал — его данные убираются, а не застывают: старый снимок читался бы как текущий.
5. Письма роя Пульт не читает и не хранит.

| Команда / событие | Данные | Когда |
|---|---|---|
| `get_fleet` | — → `FleetView` | по запросу |
| `pult://fleet` | `FleetView` | изменилось что-то, кроме `takenAt`: событие хаба, перечитанный снимок (раз в 30 с), локальные файлы (раз в 5 с) |

## 6. Панель задач

Вкладка «Задачи» — только чтение канов из панели задач команды. Ядро ходит в её API
(`GET /api/me`, `/api/tasks`, `/api/task/{KEY}`, `/api/projects`, `/api/epics`, `/api/overview`)
с заголовком `Authorization: Bearer <токен>` и пределом 8 с. Адрес — в `panel.json` папки данных
(в коде его нет: репозиторий публичный), токен — в системной связке ключей (служба
`ru.raspizdiys.pult`, запись `panel-token`). Интерфейс токен не получает никогда.

Каждый удачный ответ сохраняется в `panel-cache/<ключ>.json` вместе со временем получения.
Ошибка (нет сети, таймаут, 5xx, не тот ответ) отдаёт сохранённое с `stale: true` и фактом
ошибки; 401/403 — отдельная проблема `auth`, сохранённое при этом тоже отдаётся. Смена адреса
панели стирает сохранённое: задачи другой панели за «данные от 14:32» не выдаются.

```ts
type Problem = 'noUrl' | 'noToken' | 'auth' | 'unavailable';
type TaskState = 'todo' | 'doing' | 'review' | 'done' | 'cancelled' | 'unknown'; // ' ' '/' '?' 'x' '-' и незнакомое

interface Fetched<T> {
  data: T | null;          // null — ни свежего ответа, ни сохранённого
  fetchedAt: string | null; // когда получены data
  stale: boolean;           // data из сохранённого, свежий запрос не удался
  problem: Problem | null;
  error: string | null;     // факт: «нет ответа за 8 с», «панель ответила 401: неизвестный токен»
}

interface Task {
  key: string | null;      // у старых задач хранилища ключа нет
  keyNum: number | null;
  epicNum: number | null;  // родитель — номер задачи в том же проекте
  state: TaskState; title: string; priority: number | null; kind: string | null;
  isEpic: boolean; who: string | null; project: string; tags: string[];
  created: string | null; updated: string | null; takenAt: string | null; doneAt: string | null;
}
interface TaskRef { key: string | null; title: string; state: TaskState; priority: number | null; who: string | null }
interface TaskDetail extends Task { body: string | null; journal: string[]; parent: TaskRef | null; kids: TaskRef[] }
interface Epic { key: string | null; keyNum: number | null; title: string; state: TaskState; project: string; total: number; done: number }
interface Overview { open: number; total: number; closedWeek: number; closedMonth: number;
  byState: { todo: number; doing: number; review: number; done: number; cancelled: number } }
interface PanelConfig { url: string | null; tokenSet: boolean; tokenError: string | null }
```

| Команда | Аргументы | Ответ |
|---|---|---|
| `panel_config` | — | `PanelConfig` |
| `panel_set_url` | `{ url: string \| null }` | `PanelConfig` (только http/https) |
| `panel_set_token` | `{ token: string \| null }` | `PanelConfig`; `null` удаляет токен из связки |
| `panel_tasks` | `{ mine: boolean }` | `Fetched<Task[]>`; «мои» — фильтр `who` самой панели по имени из `/api/me` |
| `panel_task` | `{ key: string }` | `Fetched<TaskDetail>`; ключ — только буквы, цифры, дефис |
| `panel_projects` | — | `Fetched<string[]>` |
| `panel_epics` | — | `Fetched<Epic[]>` |
| `panel_overview` | — | `Fetched<Overview>` |

## 7. Эта машина: MCP-серверы

MCP-серверы — локальные настройки Claude каждого человека, поэтому в инвентарь они не входят:
Пульт находит их сам и показывает отдельной площадкой «Эта машина», в папке «MCP». Узлы
синтетические: в инвентарь не пишутся, через движок не проходят, уведомлений не дают.

Откуда берутся (одинаковые описания из разных мест — один узел, источники перечислены):
`~/.claude.json` — общие `mcpServers` и `projects[каталог].mcpServers`; `.mcp.json` в домашнем
каталоге и в каталогах проектов из `~/.claude.json` (сервер из `disabledMcpjsonServers` проекта
помечен «выключен в настройках Claude»); `claude_desktop_config.json` приложения Claude Desktop
(macOS — `~/Library/Application Support/Claude/`, Windows — `%APPDATA%\Claude\`). Серверы плагинов
и подключения claude.ai не читаются.

```ts
// NodeView узла: id = '#mcp/<имя>' ('#mcp/<имя>/2' — второе, иное описание с тем же именем),
// kind = 'mcp', project = 'MCP', on = null. В инвентаре id с «#» не бывает; при совпадении
// побеждает узел инвентаря.
interface McpInfo {
  transport: 'stdio' | 'http' | 'sse';
  sources: string[];         // «Claude Code: все проекты», «~/work/shop/.mcp.json», «Claude Desktop»
  command: string | null;    // имя исполняемого файла (stdio)
  script: string | null;     // аргумент, если это существующий файл (stdio)
  host: string | null;       // схема и хост адреса, без пути и запроса (http, sse)
  envNames: string[];        // имена переменных окружения
  headerNames: string[];
}
interface McpProbe { ok: boolean; fact: string }
```

**Секреты.** Значения `env`, заголовков и аргументы командной строки не попадают ни в снимок, ни
в события, ни в лог — только в память ядра, для настоящей проверки. Всё, что сервер написал сам
(stderr, тело ошибки), перед показом маскируется: значения `env`, заголовков, параметров адреса и
флагов с говорящим именем (`--api-key`, `--token=…`) заменяются на `***`.

Состояние узла (раз в 30 с и по `recheck`, без побочных эффектов):

| Что видно | `own` | Корень |
|---|---|---|
| stdio: есть процесс сервера — «запущен, процессов: N» | `ok` | нет |
| stdio: процесса нет — «сейчас не запущен: стартует вместе с сессией Claude» | `unchecked` | нет |
| http, sse: порт адреса открыт (запроса и заголовков авторизации нет) | `ok` | нет |
| http, sse: порт недоступен | `fail` | нет |
| настоящая проверка не прошла | `fail` | **да** |

1. Процесс сервера ищется по командной строке: в ней должны быть все аргументы-значения из настроек
   (путь к скрипту, имя пакета); без таких аргументов — по имени команды.
2. Настоящая проверка — только `mcp_probe`. stdio: сервер запускается как в настройках (команда,
   аргументы, `env`, каталог проекта), получает `initialize`, `notifications/initialized` и
   `tools/list`; предел 20 с; затем процесс и его потомки завершаются. На это время у сервера
   появляется вторая копия — интерфейс пишет это рядом с кнопкой. http: `initialize` по адресу с
   заголовками из настроек; sse: открывается ли поток событий. Итог: «отвечает · инструментов: N»
   или ошибка с хвостом stderr.
3. Итог настоящей проверки остаётся строкой `mcp` в `checks`. Отказ держится до следующего
   `mcp_probe` этого узла: пассивное наблюдение его ни подтвердить, ни опровергнуть не может
   (процесс жив — не значит, что отвечает). Снимается сам, если описание сервера в настройках
   изменилось или Пульт перезапущен. Пока держится — узел корень: красная карточка, счётчик в трее.
4. `confirmed` всегда `true`, `blockedBy` пуст. Переходы `own` пишутся в историю (`get_history`).
5. Без инвентаря карты нет: одни узлы MCP её не открывают.
