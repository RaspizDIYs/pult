# Архитектура Пульта

Выжимка плана. Реальные адреса, имена хостов и список сервисов здесь намеренно не
приводятся — они живут в приватном репозитории инвентаря.

## Зачем

Сервисов много, а понять, что из них живо, можно только через консоль. Нужен ярлык на
компьютере: открыл — и деревом видно, что работает, что нет и **почему**. Работает
локально, без промежуточного сервера.

## Принципы

1. **Проверки выполняет само приложение, с машины пользователя.** Упали и прод, и дом —
   приложение всё равно открывается и показывает именно это.
2. **Инвентарь — данные, а не код.** Один машиночитаемый файл описывает узлы,
   зависимости, проверки и способы входа. Его читают и приложение, и ИИ-агенты.
3. **Только чтение в первой версии.** Никаких «перезапустить контейнер», пока карта не
   заработала.
4. **Каждый экран независим.** Недоступный внешний источник не ломает карту.
5. **Обновления проверяются раньше функций** — этап 0 целиком про них.

## Устройство

```
src-tauri/src/
  inventory/   загрузка и проверка инвентаря, локальная копия
  probes/      проверки: tcp, http, сбор по ssh, llm, локальные порты
  engine/      расписание, граф зависимостей, вывод причины
  store/       SQLite: история переходов, кэш ответов внешних источников
  sources/     клиенты панели задач и хаба роя
  commands.rs  команды и события для интерфейса (появится на этапе 1)
src/           карта, карточка узла, логи, рой, задачи, настройки
```

Ядро на Rust шлёт интерфейсу снимок состояния и поток изменений через события Tauri.
Встроенного HTTP-сервера нет.

## Инвентарь

Отдельный приватный репозиторий. Приложение держит его локальный клон и обновляет через
`git pull` по SSH — отдельный вход и токены не нужны. Нет сети — работает на последней
копии и пишет, от какого она времени.

```yaml
версия_схемы: 1
узлы:
  - id: хост-а
    название: Хост А
    вид: хост
    зависит_от: [интернет]
    проверки:
      - {вид: tcp, адрес: "host-a.example.com:22"}
    доступ:
      как_зайти: ssh хост-а
      секрет: "хранилище → SSH-ключ хоста А"   # указатель, не значение
      у_кого: [пользователь-1, пользователь-2]

  - id: вм-б
    вид: вм
    зависит_от: [туннель-дом, гипервизор]
    сбор: {через: хост-а, команда: "ssh user@10.0.0.2"}

  - id: сервис-в
    вид: контейнер
    на: вм-б
    проверки:
      - {вид: http, url: "https://service.example.com/health"}
```

- Контейнеры, которых нет в инвентаре, но которые видны в `docker ps`, появляются на
  карте сами с пометкой «не описан».
- Личные узлы — второй файл той же схемы в локальной папке приложения.
- Секретов в инвентаре нет: только указатели, где их взять.
- У файла есть `версия_схемы`. Старое приложение на новом инвентаре пишет «обнови Пульт»,
  а не падает; незнакомые поля игнорирует.

## Проверки

| Вид | Что делает | Что даёт |
|---|---|---|
| `tcp` | соединение с портом | хост жив / порт закрыт |
| `http` | GET, код и время ответа | прокси жив, а сервис за ним нет |
| `ssh-сбор` | один сеанс `ssh` в минуту на цепочку, скрипт только читает | `docker ps`/`inspect`, состояние туннеля, список ВМ гипервизора |
| `llm` | короткий запрос к локальным моделям | отвечает ли модель, текст ошибки |
| `локальный-порт` | порты туннелей на своей машине | живы ли туннели |

Сбор идёт системным `ssh` (есть и на маке, и в Windows 10+), поэтому работают те же
алиасы, что в консоли. Машины за туннелем достижимы только через промежуточный хост,
поэтому один сеанс за цикл собирает всю цепочку.

Быстрые проверки (tcp, http) — раз в 30–60 секунд, сбор по ssh — раз в минуту.

## Причина отказа

Каждый узел знает, от чего зависит. Если сломан родитель, дети не краснеют каждый сам по
себе, а показывают «недоступен, причина выше: …». Красным горит только корень проблемы.

| Что не прошло | Надпись на карточке |
|---|---|
| проба наружу с моей машины | «У тебя нет интернета» |
| GitHub недоступен, остальное живо | «Нет VPN» |
| ssh-порт промежуточного хоста | «Прод не отвечает» |
| туннель до дома давно без рукопожатия | «Дом не на связи: свет или интернет» |
| гипервизор жив, ВМ не запущена | «ВМ выключена или зависла» |
| ВМ жива, контейнер не запущен | «Контейнер упал: код 137, нехватка памяти» + хвост лога |
| контейнер жив, `/health` не 200 | «Сервис не отвечает: 502» |

По клику на карточку: состояние, причина, последние проверки, как зайти, логи
(`docker logs` по запросу, со слежением, пока вкладка открыта).

Единственный обязательный автотест первой версии — движок причин на фикстурах:
«сломан родитель → дети серые, причина одна».

## Рой и задачи

- **Рой** — снимок и поток событий хаба агентов через локальный туннель; токен читается
  из локального конфига оркестратора, новых секретов не нужно. Показывает сессии по
  машинам и локи с держателем и очередью; отдельно — лок, который держит сессия не в сети.
- **Задачи** — клиент API панели задач, личный токен в системной связке ключей. Каждый
  удачный ответ кэшируется в SQLite; когда панель недоступна, показывается кэш с временем.
  В первой версии — только просмотр.

## Уведомления

Приложение сидит в трее и показывает системное уведомление при смене состояния — после
двух неудачных проверок подряд, чтобы не дёргать на единичный сбой. Уведомления в
мессенджер — позже и с сервера, иначе двое с открытым Пультом получат каждое дважды.

## Обновления

- `tauri-plugin-updater`, фид —
  `https://github.com/RaspizDIYs/pult/releases/latest/download/latest.json`.
  Репозиторий публичный, поэтому скачивание не зависит от нашей инфраструктуры.
- Сборка в GitHub Actions по тегу `v*`: macOS (universal) + Windows. Релиз создаётся
  черновиком и публикуется отдельной задачей, только когда собрались **обе** платформы.
- Проверка при запуске и раз в 6 часов, плашка с текстом изменений; посреди работы само
  не перезапускается. Ошибка проверки — в лог и в строку статуса.
- Windows: NSIS для текущего пользователя, без подписи кода. macOS: подпись ad-hoc, без
  учётки разработчика Apple.
- Ключ подписи обновлений — в секретах Actions и копией в хранилище паролей.

## Доступы (этап 4, пока только проект)

Три слоя, один источник правды — инвентарь:

1. **Справочник** — блок `доступ` у узла: как зайти, у кого есть доступ, где секрет.
2. **Хранилище** — готовое (Vaultwarden или Bitwarden), свой сейф не пишем. Инвентарь
   ссылается на записи по имени.
3. **Выдача кнопкой** — роль описана в инвентаре; процедура запускается с машины
   администратора под его правами: сухой прогон со списком изменений, потом подтверждение.

Серверного компонента с правами администратора нет намеренно: его взлом отдал бы всё сразу.

## Этапы

0. **Каркас и обновления.** Два репозитория, пустое приложение, сборка под обе ОС,
   релиз 0.0.1 → 0.0.2 с проверкой автообновления на маке и на винде.
1. **Карта.** Инвентарь, проверки, вывод причины, карта, карточка, логи, трей и
   уведомления, история переходов, экран роя, задачи на просмотр.
2. **Действия и запись.** Правка задач с очередью на отправку, перезапуск контейнера и
   снятие зависшего лока с подтверждением.
3. **Круглосуточный догляд.** Тот же движок без окна на сервере, уведомления в мессенджер.
4. **Студия.** Проекты, профили, доступы, поиск по заметкам.

## Ограничения

- Машины за туннелем видны только через промежуточный хост: если он лежит, про них
  снаружи узнать нельзя — карточки покажут «неизвестно: единственный путь недоступен».
- Локальное приложение видит, только пока запущено; историю «что падало ночью» даст этап 3.
- Без доступа к GitHub не пройдут проверка обновлений и `git pull` инвентаря — приложение
  работает на последней копии и говорит об этом.
