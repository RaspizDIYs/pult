# Пульт

Локальное приложение для macOS и Windows: карта хостов, виртуальных машин, контейнеров
и сервисов RaspizDIYs. На карточке узла видно не только «лежит», но и **почему** —
красным горит корень проблемы, зависимые узлы показывают «причина выше».

Проверки выполняет само приложение с машины пользователя: между ярлыком и картой нет
нашего сервера, поэтому Пульт открывается и тогда, когда упало всё остальное.

> Версия 0.3: карта-дерево с причинами отказа, сбор по ssh, логи, трей и уведомления,
> вкладки «Рой» и «Задачи». Устройство — [docs/архитектура.md](docs/архитектура.md), данные
> между ядром и интерфейсом — [docs/контракт.md](docs/контракт.md).

## Возможности

Есть сейчас:

- карта узлов из инвентаря (каталог с `инвентарь.yaml`, обычно git-клон — подтягивается сам);
  пример — [examples/инвентарь.yaml](examples/инвентарь.yaml), его берёт режим разработки.
  Карта — дерево, как в проводнике: площадка → ВМ и LXC → папки проектов (`проект`) → сервисы;
  свёрнуто до площадок, ветки с отказом раскрываются сами; служебное можно убрать с карты `скрыть: true`;
- проверки tcp и http с этой машины раз в 30 секунд, сбор по ssh раз в минуту: контейнеры,
  ВМ и LXC Proxmox, WireGuard, проверки изнутри закрытой сети; неописанные контейнеры видны сами;
- причина отказа: красным горит корень, зависимые — «причина выше»; «неизвестно» и
  «устарело» отдельно от «работает» и «отказ»;
- логи контейнера в карточке, история переходов состояния;
- LLM на карте: проверка `ollama` спрашивает у сервера список моделей и что сейчас в памяти —
  «отвечает за 40 мс · моделей: 5 · в памяти: qwen3:8b (GPU)», «не отвечает: …» или «нет модели X»
  (`ожидать_модели`); работает и с этой машины, и изнутри закрытой сети (`откуда`);
- MCP-серверы этой машины — площадка «Эта машина», папка «MCP»: Пульт сам читает настройки Claude
  Code и Claude Desktop и показывает, какие серверы описаны, откуда взяты и запущены ли сейчас
  (у http — доступен ли адрес). Значения переменных окружения, заголовки и аргументы не
  показываются и в лог не пишутся — только имена;
- вкладка «Задачи» — каны панели задач команды, только просмотр: адрес панели и токен — в
  настройках (токен хранится в системной связке ключей); последний ответ сохраняется, и без
  сети видно сохранённое с пометкой, от какого оно времени;
- трей со сводкой, уведомления только о подтверждённых отказах и восстановлениях корней,
  автозапуск при входе в систему. Закрытие окна приложение не завершает: оно проверяет
  дальше, а на маке уходит из Dock и Cmd-Tab и остаётся значком в строке меню. Окно вернуть —
  «Открыть» в меню значка (или значок в Dock/запуск приложения ещё раз), выйти совсем —
  «Выход» там же или Cmd+Q при открытом окне. Пульт всегда один: повторный запуск не создаёт
  второй процесс, а показывает окно уже работающего;
- автообновление из GitHub Releases: проверка при запуске и раз в 6 часов, плашка
  «Доступна X — обновить и перезапустить» с текстом изменений. Само не перезапускается;
- ошибка проверки (нет сети, нет VPN) работе не мешает: пишется в лог и в строку
  «Обновления» внизу окна;
- диагностические флаги для проверки обновления скриптом, без окна:

  | Флаг | Что делает | Вывод |
  |---|---|---|
  | `--check-update` | спрашивает фид и выходит | `current=0.0.1`, `available=0.0.2` (пусто — обновлений нет) |
  | `--apply-update` | то же, затем скачивает, ставит и выходит | плюс `installing=…`, `installed=…` |

  Код выхода 0 — проверка прошла, 1 — ошибка (текст в `error=…` в stderr).

  ```sh
  # macOS
  /Applications/Pult.app/Contents/MacOS/pult --check-update
  ```

  ```powershell
  # Windows: | Out-Host — чтобы PowerShell дождался оконного приложения и показал вывод
  & "$env:LOCALAPPDATA\Pult\pult.exe" --check-update | Out-Host
  ```

  На Windows `--apply-update` запускает установщик и выходит сразу, не дожидаясь конца
  установки: перед повторным `--check-update` подожди несколько секунд.

  На маке копия с карантином (только что скачанная, ещё ни разу не открытая) из терминала
  не запускается: флаги `--check-update` молча висят. Сначала открой Пульт один раз из «Программ».
  Если Пульт запущен из временной копии macOS (App Translocation), `--apply-update` ничего
  не ставит: пишет в `error=…`, как это исправить (см. «Установка»), и выходит с кодом 1.

Чего Пульт не делает сам — только по кнопке в панели узла, и рядом с кнопкой сказано, чем она
обернётся:

- **«Спросить модель»** — настоящая генерация на один токен выбранной моделью. В цикле её нет:
  она грузит модель в память сервера и может вытеснить ту, что сейчас занята рабочими запросами;
- **«Проверить по-настоящему»** — рукопожатие с MCP-сервером (`initialize` и `tools/list`). Для
  stdio это запуск второй копии сервера на несколько секунд (потом она гасится вместе с
  потомками), поэтому серверы, которые держат устройство или сессию, проверять так не стоит.
  Отказ такой проверки остаётся красным на карте до следующего нажатия: по тому, что видно
  со стороны, его не снять.

Не запущенный MCP-сервер — не отказ: серверы stdio живут, только пока открыта сессия Claude.

## Рой

Вкладка «Рой» рядом с картой — кто из ИИ-агентов в сети, кто что держит и где беда.
Только чтение: снять чужой замок или написать в рой отсюда нельзя.

Откуда данные:

- **хаб роя** ([agent-orchestrator](https://github.com/RaspizDIYs/agent-orchestrator)) —
  снимок `GET /state` и поток `/events`: сессии всех машин, общие замки (`deploy`, `push`,
  `db-migrate`, `test-stand`) и очередь к ним, доска, заявки на файлы, задачи брокера.
  Адрес и токен — из того же `fleet.json` локального диспетчера, что читает CLI роя;
  токен в интерфейс не попадает. Письма роя Пульт не читает;
- **локальный диспетчер** этой машины (`~/.claude/orchestrator`) — ёмкость машины, идущие
  прогоны, локальные замки и очереди, имена сессий. Видно и тогда, когда хаб недоступен:
  тогда это сказано плашкой, а общие замки и другие машины не показываются вовсе, а не
  застывают на последнем снимке. Битый файл диспетчера — строка с ошибкой, остальное видно.

Сессия называется своим именем; если имени нет — машиной, папкой и последней заметкой,
рядом всегда начало идентификатора, которым её называют агенты («чат 4b9c»).

Проблемой считается — и выносится наверх, в число «проблем: K»:

- замок держит сессия **не в сети** (хаб её не слышал больше часа или она завершилась);
- замок держится **дольше срока** своего ресурса;
- держатель в сети, но **молчит** 20 минут и дольше (две пропущенные отметки клиента);
- один файл заявили **две живые сессии** — заявка ушедшей пересечением не считается.

Без Tauri, в браузере, вкладка работает на выдуманных данных; сценарий задаётся
параметром `?fleet=`: `problems`, `calm`, `hub-down`, `off`, `empty`, `loading`.

## Установка

Скачать со страницы [последнего релиза](https://github.com/RaspizDIYs/pult/releases/latest):

- **macOS** — `Pult_<версия>_universal.dmg` (Apple Silicon и Intel). Открой образ и
  **перетащи `Pult.app` в «Программы» в Finder**. Не копируй приложение командой `cp -R` и не
  запускай его прямо из «Загрузок» или из образа: файл остаётся с карантином, и macOS
  открывает его из временной копии только для чтения (`…/AppTranslocation/…`). Такая копия
  работает, но обновиться не может: замена файлов падает с «Read-only file system». Пульт
  сам узнаёт такой запуск и пишет, что делать.
  Приложение подписано ad-hoc, без учётки разработчика Apple, поэтому при первом запуске
  macOS его не пустит. Первый запуск — через «Системные настройки → Конфиденциальность и
  безопасность → Всё равно открыть» (кнопка появляется после первой неудачной попытки открыть).
  Если Пульт уже запущен из временной копии: закрой его, перетащи `Pult.app` в «Программы»
  через Finder заново (или вынеси из «Программ» и верни обратно) и открой снова.
  Либо из терминала: `xattr -dr com.apple.quarantine /Applications/Pult.app` — без карантина
  временной копии нет.
- **Windows** — `Pult_<версия>_x64-setup.exe`, ставится для текущего пользователя, без
  прав администратора. Подписи кода нет: SmartScreen предупредит («Подробнее →
  Выполнить в любом случае»). Репутация у неподписанного файла набирается заново для
  каждой версии, так что предупреждение может повторяться на каждом новом установщике.

Дальше обновления ставятся из самого приложения.

## Стек

Tauri v2 (Rust) + React 19 + Vite + TypeScript + Tailwind v4 + shadcn/ui,
`@xyflow/react` для карты. Обновления — `tauri-plugin-updater` (версия закреплена
точно), подпись — ключом minisign из секретов Actions. Пакетный менеджер — npm.

## Разработка

Нужны Node.js (LTS), Rust stable, на Windows — WebView2 (есть в Windows 10/11).

```sh
npm install
npm run tauri dev        # окно с горячей перезагрузкой
npm run build            # tsc + vite build
cd src-tauri && cargo check && cargo test
```

`npm run dev` без Tauri тоже открывается в браузере, но API Tauri там нет: версия
покажется как «—», проверка обновлений — ошибкой.

Полную сборку установщика локально обычно не нужно: её делает CI. Если всё же надо —
`npm run tauri build` (без подписи обновлений; подписанные артефакты собираются только в CI).

## Релиз

Версия хранится в одном месте — `package.json`; `src-tauri/tauri.conf.json` ссылается
на него. Текст изменений берётся из аннотации тега и показывается в плашке обновления.

```sh
npm version 0.0.2 --no-git-tag-version
git commit -am "chore(release): 0.0.2"
git tag -a v0.0.2 -m "Что изменилось — коротко, по-русски"
git push origin main v0.0.2
gh run watch
```

Что делает `.github/workflows/release.yml`:

1. проверяет, что тег совпадает с версией в `package.json`, и создаёт **черновик** релиза;
2. собирает macOS (`universal-apple-darwin`, `.app` + `.dmg`) и Windows (NSIS) параллельно,
   с подписью обновлений; без секретов подписи сборка падает;
3. одна завершающая задача собирает `latest.json` из файлов черновика (`darwin-aarch64`,
   `darwin-x86_64`, `windows-x86_64`), проверяет подписи и версию и только потом
   публикует релиз. Не собралась хоть одна платформа — релиз остаётся черновиком,
   а фид продолжает отдавать прошлую версию.

Фид обновлений: `https://github.com/RaspizDIYs/pult/releases/latest/download/latest.json`.

Секреты репозитория: `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.
Публичный ключ — в `plugins.updater.pubkey`. Потерять приватный ключ значит потерять
возможность обновить всех, кто уже установил Пульт.

## Структура

```
src/                     интерфейс (React): карта, карточка узла, логи, настройки
  lib/pult.ts            команды и события ядра (типы — из docs/контракт.md), макет для браузера
  lib/updater.ts         проверка и установка обновлений
src-tauri/
  src/lib.rs             запуск, плагины, трей, флаги --check-update / --apply-update / --hidden
  src/inventory/         инвентарь: разбор, проверка, принятый снимок, git pull
  src/engine/            оценка состояний и причин (чистая функция), входные факты
  src/probes/            проверки tcp, http и ollama с этой машины
  src/collect/           сбор по ssh: скрипт только для чтения, разбор, поток логов
  src/adapter.rs         инвентарь → планы сбора, отчёт сбора → факты движка
  src/mcp/               MCP-серверы этой машины: настройки Claude, состояние, настоящая проверка
  src/monitor.rs         циклы проверок и сбора, события для интерфейса
  src/store/             настройки и история переходов (JSONL)
  src/sources/           клиенты панели задач и хаба роя
  tauri.conf.json        конфиг приложения и обновлений
  tauri.ci-updater.json  включает артефакты обновления в CI
.github/workflows/       verify.yml (проверка на push/PR), release.yml (релиз по тегу)
docs/архитектура.md      устройство приложения и этапы
```

Инвентарь (список узлов и адресов) хранится в отдельном приватном репозитории —
в этом, публичном, адресов инфраструктуры нет и быть не должно.
